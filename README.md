# cord-dotnet

A C# / .NET 10 fork of **cord**, a Python ETL for customs paperwork, re-targeted at the
Microsoft cloud. It covers one document type, the waybill (TTN): a `^`-delimited export lands in
Azure Blob Storage, an Azure Function validates it row by row, and the valid rows are upserted
into a Dataverse table, where Power Apps, Power Automate and Dynamics 365 can use them.

```
ttn_*.csv ──► Blob Storage ──► Azure Function ──► Dataverse  cord_waybill
              waybills/incoming   validate rows      UpsertMultiple on an alternate key
                                       │
                                       └──► waybills/reports/<file>.json   rejected rows and why
```

## Projects

| Project | |
|---|---|
| `src/Cord.Core` | `Waybill` records, `^`-file reader, row validation, LINQ flattening. No cloud dependencies. |
| `src/Cord.Dataverse` | Maps waybills onto the `cord_waybill` table, bulk upserts, managed identity sign-in. |
| `src/Cord.Functions` | Blob-triggered Azure Function (isolated worker), writes a JSON report per file. |
| `tests/Cord.Tests` | xUnit v3: parsing rules, Dataverse mapping, parity with the Python original. |

## Highlights

- **LINQ `SelectMany`.** It flattens several input files into one stream of rows, each tagged with
  its file and row number, and merges the per-row errors into one list
  (`WaybillValidation`). It also flattens nested records into columns: `Flat.Columns<Waybill>()`
  turns `Seller.TaxPayerId` into a column, depth first. That walk names the Dataverse columns and
  gives the header and rows a spreadsheet export needs.
- **Dataverse bulk upsert.** `UpsertMultiple` runs in batches of 500, matched on an alternate key
  (`cord_globaluniqueidentifier`), so re-importing a file or a Functions retry never creates
  duplicates. One request can't contain the same key twice, so repeated rows are collapsed to the
  last occurrence first.
- **No secrets.** `ServiceClient` gets its tokens from `DefaultAzureCredential`: the Function App's
  managed identity in Azure, and `az login` on a developer machine.
- **Parity with the original.** `Fixtures/ttn_mock.csv` was generated by the Python project's mock
  data generator. A test checks that this port accepts and rejects exactly the rows the Python
  validator does.
- **Build setup.** .NET 10, central package management (including a pin that overrides a vulnerable
  transitive package of the Dataverse client), warnings as errors, and CI on GitHub Actions.

## Dataverse table

Create a `cord_waybill` table (publisher prefix `cord`) with `cord_number` as its primary column.
Column names are the flattened property paths in lower case (`WaybillTable.ColumnName`).

| Columns | Type |
|---|---|
| `cord_registration` (required), `cord_crossedat`, `cord_correctiondate` | Date only |
| `cord_itemprice`, `cord_priceinnationalcurrency` | Decimal, 2 places |
| `cord_globaluniqueidentifier` | Text (64), **alternate key** |
| `cord_itemfeacncode` | Text (10) |
| every other column (`cord_statedgoal`, `cord_sellername`, `cord_buyertaxpayerid`, ...) | Text; 200 characters for the address and terminal columns |

The identity that runs the function needs an **application user** in the environment (Power
Platform admin center → Environment → Settings → Application users) with a security role that can
create and update `cord_waybill`.

## Run locally

You need the [Azure Functions Core Tools](https://learn.microsoft.com/azure/azure-functions/functions-run-local),
[Azurite](https://learn.microsoft.com/azure/storage/common/storage-use-azurite) and the Azure CLI.

```sh
cp src/Cord.Functions/local.settings.example.json src/Cord.Functions/local.settings.json
# set Dataverse__Url to your environment, then:
az login                          # DefaultAzureCredential signs in with this account
azurite --silent --location .azurite &
(cd src/Cord.Functions && func start)

# in another terminal
az storage container create -n waybills --connection-string UseDevelopmentStorage=true
az storage blob upload --connection-string UseDevelopmentStorage=true \
   -c waybills -n incoming/ttn_mock.csv -f tests/Cord.Tests/Fixtures/ttn_mock.csv
az storage blob download --connection-string UseDevelopmentStorage=true \
   -c waybills -n reports/ttn_mock.json -f /dev/stdout
```

The signed-in account must have access to the Dataverse environment.

## Deploying

Deploy `src/Cord.Functions` to a Function App with a system-assigned managed identity. Then:

- Register the identity as a Dataverse application user (see above).
- Set the app settings `Dataverse__Url` and `CordStorage`. For a secretless storage connection, use
  `CordStorage__blobServiceUri` and give the identity *Storage Blob Data Owner*.
- On the Flex Consumption plan, blob triggers must use Event Grid: set
  `Source = BlobTriggerSource.EventGrid` on the trigger and create an Event Grid subscription.

## Differences from the Python original

- Prices are parsed as `decimal`, with a decimal point or comma. The Python code keeps them as
  float or raw text, and has a TODO to switch to `Decimal`.
- Dates must be exactly `dd.MM.yyyy`.
- `global_unique_identifier` must not be blank, because it is the upsert key.
- Empty text is stored as null in Dataverse.
- Out of scope so far: declarations, clearance statements, department routing and the xlsx reports.
  `Flat.Columns<T>()` already provides what an Excel export needs: one header row and one row of
  values per record.
- Mock data generation stays in the Python project.
